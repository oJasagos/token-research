# Схема отчёта

Каждый отчёт — один файл `data/reports/<slug>.json`. Плюс запись в `data/index.json`.

**Все поля опциональны кроме `slug` и `symbol`.** Рендерер пропускает пустые секции: если нет
`derivatives` — вкладки «Деривативы» просто не будет. Лучше опустить поле, чем поставить выдуманное значение.

## `data/index.json`

```json
{
  "updated": "2026-07-28",
  "reports": [
    {
      "slug": "hype",            // = имя файла в data/reports/
      "symbol": "HYPE",
      "name": "Hyperliquid",
      "chain": "Hyperliquid L1", // становится фильтром на главной
      "date": "2026-07-28",
      "stance": "neutral",       // bullish | neutral | bearish | watch | avoid
      "price": 55.46,
      "change24h": -3.81,        // в процентах
      "mcap": 12335747203,
      "summary": "1–2 предложения для карточки"
    }
  ]
}
```

## `data/reports/<slug>.json`

Единицы: **все суммы в USD, числом без разделителей**. Проценты — числом (`-3.81` = −3.81%),
кроме долей, помеченных ниже как *доля* (`0.42` = 42%). Даты — `YYYY-MM-DD`.

## Разметка в тексте

В любом текстовом поле работает: `**жирный**`, `` `моноширинный` ``, перенос строки, пустая строка = абзац.
HTML экранируется — вставлять теги нельзя.

## Графики

Любая секция (`market`, `onchain`, `fundamentals`, `derivatives`, `narrative`) может нести
массив `charts`. Каждый график рисуется SVG прямо в браузере, без библиотек, и всегда
сопровождается раскрывающейся таблицей с числами.

```jsonc
"charts": [
  {
    "type": "area",            // тренд во времени: линия с заливкой, кроссхэйр и тултип
    "title": "КОМИССИИ ПО МЕСЯЦАМ",
    "unit": "usd",             // usd | coins | pct | (пусто = просто число)
    "series": [ { "label": "янв 25", "value": 52165603 } ],
    "note": "Подпись под графиком"
  },
  {
    "type": "bars",            // сравнение величин
    "emphasis": 2,             // индекс важной полосы, остальные приглушаются
    "series": [ { "label": "…", "value": 100, "display": "100 млн" } ]
  },
  {
    "type": "compare",         // полярность: две встречные величины
    "series": [ { "label": "Сжигание", "value": 840000, "tone": "pos" },
                { "label": "Разлок",   "value": 9920000, "tone": "neg" } ],
    "ratio": "Строка с выводом под полосами"
  }
]
```

`display` перебивает автоформат значения. `tone` это `pos` (зелёный) или `neg` (красный) -
только там, где направление и есть смысл.

**Лесенка сценариев** строится сама, если у каждого сценария в `scenarios` есть числовое
поле `value`. Она показывает цели относительно текущей цены. Нет `value` - рисуются
обычные карточки.

## Цвета графиков

Категориальный набор `#7c83ff, #00a3b4, #e0704f, #b06ae0` (в этом порядке) проверен
валидатором из скилла `dataviz` против фона `#111114`: проходит все шесть проверок,
включая различимость соседних пар при дальтонизме. Менять порядок или подставлять
другие цвета без повторной проверки не стоит - привычные зелёный и жёлтый из темы
эту проверку не проходят.

Зелёный и красный используются как **статусные**, а не категориальные: только там,
где цвет означает направление.

## Живые цены

Цена и капитализация тянутся с биржи прямо в браузере читателя. Источник задаётся
на отчёт, а не угадывается по тикеру:

```jsonc
"market": {
  "price": 52.18,                 // цена на дату отчёта, она же опорная для проверки
  "live": { "venue": "gate", "pair": "HYPE_USDT" }   // venue: binance | gate
}
```

**Почему источник задаётся вручную.** Тикеры на биржах сталкиваются. `LIT/USDT`
на Binance это Litentry - другой актив, чей рынок последний раз торговался в июле
по 0.74$, а наш LIT это Lighter по ~2$. Подключение по символу показало бы чужую
цену с полной уверенностью.

**Две защиты в `live.js`:**
- цена, отличающаяся от `market.price` больше чем на 60%, отклоняется;
- нечисловое или неположительное значение отклоняется.

Отклонённая котировка оставляет цифру отчёта - она датирована и верна.
Нет сети, заблокированный CORS, лимит запросов или открытый с диска файл дают
один и тот же результат: остаётся статическая цена и подпись «цены на дату отчёта».

Обновление раз в минуту и только при видимой вкладке. Пересчитываются от живой цены
только капитализация и FDV, потому что это цена, умноженная на предложение.
Мультипликаторы, комиссии и выводы остаются на дату отчёта.
